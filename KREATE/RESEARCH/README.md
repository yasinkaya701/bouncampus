# Core current thesis

```text
observe existing signals
        ↓
reconcile meaning / provenance
        ↓
predict or diagnose
        ↓
quantify uncertainty
        ↓
recommend before the reachable decision freezes
        ↓
human approve / edit / hold
        ↓
measure outcome + service guardrails
        ↓
learn / reject intervention
```

## First beachhead hypothesis

High-volume, centrally coordinated/institution-governed university dining where:

- a recurring production/allocation quantity decision exists;
- forecast error creates a meaningful consequence;
- current reservation/incumbent systems leave a residual decision gap;
- a reachable operator can act before a freeze point;
- actual consumption and surplus/shortage can be measured;
- a repeatable user/buyer/deployment path exists.

## Not validated yet

- that Boğaziçi demand mismatch materially causes the published food-waste total;
- the Boğaziçi/TEMAŞ daily quantity owner;
- freeze time / batch flexibility;
- payment/settlement quantity;
- excess/shortage economic owner;
- service-level private data access;
- operator adoption;
- willingness to pay;
- cross-university repeatability;
- same-product/same-sales-process beachhead homogeneity;
- prioritized purchasing criteria of a real Persona;
- primary economic buyer and veto path.

# Three application PMR hypotheses

## H-A — controllable decision

A named operator determines/approves meal-production or allocation quantity before actual demand is known and has a meaningful adjustment window.

## H-B — addressable mismatch

Demand/planning mismatch repeatedly creates avoidable edible surplus and/or shortages that a better reachable decision could materially change.

## H-C — asymmetric risk

Shortage risk causes an explicit/implicit safety buffer that is currently set using fragmented information/experience rather than a consistently integrated decision process.

These remain hypotheses until real interviews create `E-INT-*` evidence.

# Forbidden research-to-claim jumps

Do not infer:

```text
public annual waste
    -> overproduction caused it

employee satisfaction score
    -> that factor caused food waste

another university contract
    -> Boğaziçi uses same contract logic

BUCard/QR exists
    -> historical aggregate dataset is accessible

reservation system exists
    -> forecasting problem is solved

academic forecasting result
    -> our model will achieve same accuracy/saving

competitor public page omits feature
    -> competitor cannot do feature

208 universities
    -> 208 addressable customers

UI GreenMetric digital criterion
    -> university will buy BOUNCAMPUS

camera leftover paper works
    -> TrayGate has validated gram accuracy

real staff title exists
    -> that person owns production quantity

same technical pain at two universities
    -> same beachhead sales process

public procurement threshold
    -> guaranteed direct-purchase route

TEMAŞ public waste-awareness post
    -> TEMAŞ needs/will buy BOUNCAMPUS
```

# Research maintenance rule

When new evidence arrives:

1. store the narrow source/claim in `EVIDENCE.md` if promotable;
2. update relevant assumption state only if evidence directly supports/rejects it;
3. add a KEEP/MODIFY/KILL decision only when product/application behavior actually changes;
4. preserve contradictory evidence;
5. never overwrite `UNKNOWN` with team preference.
